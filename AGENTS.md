# AGENTS.md

Guidelines for any agent working in this repository. Read this, then `STATE.md`, then
[docs/00-requirements.md](docs/00-requirements.md). `STATE.md` is generated by `bench state`; until
slice 1 lands it may be absent, in which case `docs/` is the whole story. If this file conflicts with requirements,
requirements win for *what*; this file wins for *how*.

## What this project is

A durable data-analysis workspace for Windows. An append-only event log holds the truth; a `bench`
CLI is the only way to mutate it; a Tauri app is the viewport onto it. An agent operates it on the
user's behalf, so a fresh session must be able to pick up the project without re-litigating it.

## Non-negotiables

1. **Never edit `data/events.jsonl` directly.** All mutations go through `bench`.
2. **Never mutate `data/raw/`.** Imported files are evidence.
3. **Never delete a dataset version.** Replacing data creates a new version with a diff.
4. **Never put analysis in the entry path.** Typing a number must not wait on Python or a model.
5. **Never mix observed and derived values.** Fitted values never enter a dataset.
6. **Never draw a curve without n, DOF, an interval band, and a verdict.**
7. **Never change a point's shape silently.** Extending a shape is a recorded migration.

## How work gets done

- **Small steps.** One user-visible capability per step. Aim for a diff under ~400 lines, reviewable
  in 10 minutes. If a step needs to be bigger, split it.
- **Plan, then build, then verify.** State the intended behavior before writing code. Test the
  behavior you claimed, not just the exit code.
- **UI work is gated on the user.** Produce a screenshot plus a two-line "what to look at" note at
  100/125/150% scaling, and wait for approval. Never self-approve a visual change. Log the outcome
  in `docs/ui-review-log.md`.
- **Record irreversible choices** as a short ADR in `docs/adr/` before acting on them.
- **Don't add dependencies silently.** Name the dependency, say why, and note the size cost.
- **Update `STATE.md`** by running `bench state` after any mutation — never by hand.
- **Record decisions** the user makes ("we're using Python", "tabs instead of a sidebar") via
  `bench decide`, so the next session inherits them.

## Version control

- **`pnpm verify` means green.** It runs the typecheck and the tests. Never commit on red.
- **Commit at every good point**: each completed step, each fixed bug, each decision recorded. A
  green check plus a clean tree is the bar for ending a pass.
- **Never leave uncommitted work behind.** If a step is half-done, either finish it or revert it;
  a broken tree costs the next session more than it saves.
- **State what changed and why** in the message, and name anything deliberately left out.
- **Never rewrite history** on a branch someone else may have built on. There is one branch until
  the user asks for more.
- Regenerable output is ignored (`artifacts/`, `index.sqlite`, `node_modules/`). If a file can be
  rebuilt in one command, it does not belong in history — except fixtures, which are committed so
  the tests have something real to read.

## Definition of done

A step is done when all of these hold:

- [ ] The claimed behavior works through the interface the user actually uses.
- [ ] Tests cover it; stats code is checked against a closed-form or reference result.
- [ ] Empty, loading, error, and single-point states all render sensibly.
- [ ] Keyboard-only path works; focus is never lost or trapped.
- [ ] Renders correctly at 100/125/150% scaling.
- [ ] No layout shift or flicker when data updates.
- [ ] Perf budget respected: keystroke→paint < 100 ms, re-render < 50 ms at 10k points.
- [ ] No new dependency without a note.
- [ ] `bench check` passes.

## Visual standard

Clean, calm, dense-but-breathable. One accent color. Numbers set in a tabular/monospace face.
Charts use a restrained palette with a single emphasis hue. No gradients, no drop shadows on cards,
no icon without a label in primary flows. Design tokens live in one file; never hardcode a color or
spacing value in a component.

The app should look like an instrument, not a dashboard template.

## Where things live

```
data/events.jsonl   truth (append-only, via bench only)
data/raw/           untouched imports
shapes/             point shape registry
recipes/            analysis code (Python) with declared schemas
views/              tab and panel definitions (JSON)
artifacts/          generated output, all regenerable
index.sqlite        derived index, disposable
tasks/              in-app requests queued for the agent
docs/               requirements, ADRs, decision log, UI review log
STATE.md            generated cold-start brief
```

## When in doubt

Prefer the change that makes the next session easier to start. Prefer a visible limitation over a
confident guess. Ask the user before an irreversible choice, not after.
